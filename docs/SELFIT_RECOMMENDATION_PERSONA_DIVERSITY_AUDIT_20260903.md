# Selfit 推荐组合 × 人格适配 × 视觉相似性审计

日期：2026-09-03｜对象：当前本地 App 推荐实现及生效内容池｜性质：只读审计，未修改推荐逻辑、资产或上下架状态。

## 一、结论与验收意见

**目前已经能按人格返回不同的推荐池，但尚未达到“连续浏览时衣服不太雷同”的体验要求。应优先调整推荐组的组成与顺序，再补有明显差异的款式，而不是继续增加相似版本的数量。**

| 审计项 | 结论 | 依据 |
|---|---|---|
| 人格池隔离 | 基准样本通过 | 测试模式和正式冷启动的首 10 条都命中对应主人格标签；不代表视觉判断正确 |
| 人格视觉适配 | 部分成立，尚不能整池验收 | ICED 的冷感、JADE 的浅色东方语汇可读；BOLT、NEON、OOPS 等存在表达过度或边界混同 |
| 推荐组的新鲜度 | 不通过现有目标 | 秋季测试模式中，13/16 人格的首 10 条出现同一主服装超过 2 次 |
| 连续滚动新鲜度 | 高风险 | 16 人格各取前 30 条，336 个重叠的连续 10 条窗口中，290 个超标，占 86.3% |
| 款式、颜色、版型去重 | 只有基础，不能自动验收 | 发现 443 对轮廓及颜色近似候选；算法也存在明确误报，不能直接淘汰 |
| 审美与人格审核证据 | 不足 | 生效 1,169 套的人格审核门均为 pending；600 件单品的视觉语义审核均为 pending |

最紧急的例子：**JADE 首 10 条全部使用同一条裤子；LOOP 首 10 条有 7 条使用同一条裤子。** 即使上衣变化，用户仍会觉得“怎么还是这一套”。

## 二、范围、方法与限制

### 2.1 本次实际检查了什么

- 全量读取经过当前审核覆盖层处理的 600 件单品、1,169 套生效配方；未把原始 1,200 条中的 hold / alias 记录算进推荐池。
- 运行当前 `closet.recommend_outfits`，覆盖 16 人格 × 4 个季节参数 × 2 种模式，共 128 个受控条件；每次按当前 App 的每页 6 条、排除已返回 ID 的方式取前 30 条。
- 两种模式分别为人格测试模式、正式模式的“无个人衣橱、无历史反馈”冷启动。没有读取、使用或写入真实用户偏好。
- 秋季测试模式是报告主表的统一比较基准，符合当前 9 月 App 发送的季节参数。另四季与正式模式用于敏感性检查，不冒充 128 个独立用户样本；128 个条件实际产生 18 种不同排序。
- 逐张查看四张首屏联系表，共 96 个推荐卡片位置；另外复核 8 对、16 个单品图像位置。不是对全部 1,169 套逐张高分辨率验收。
- 使用透明单品图的轮廓和已有实测色板筛查近似项；生产提示词中的“版型”“材质”不当成已验证的图片事实。

### 2.2 指标口径

1. **同一主服装重复**：同一 top / outer / bottom / skirt / dress 单品 ID，在连续 10 条中出现的最大次数。目标沿用此前方案：最多 2 次。鞋包配饰不计入该主服装阈值，但单独检查其重复。
2. **同主角重复**：按配方 `slot_roles=hero` 统计。主角字段可能与真实视觉重心不一致，所以不能只靠此项判断新鲜度。
3. **共享单品相似对**：两套的 garment_ids 集合 Jaccard ≥0.6。前 10 条共有 45 个两两比较位置；这是候选相似对，不是淘汰套数。
4. **不同 ID 的近似款**：同品类，透明主体归一化轮廓 IoU≥0.85、原始宽高比之比在 0.8–1.25，且不透明像素色板的加权平均色 CIELAB ΔE76≤12。阈值仅用于本次筛查，尚未经人工标注集标定。
5. **人格适配**：分开报告“标签命中”和“看图是否读得出该人格”。没有独立盲审结果，不提供 Top-1 / Top-2 视觉准确率，也不把默认 affinity=0.96 解释为 96% 匹配率。

颜色测量受渲染光照、阴影和多色平均影响；轮廓不包含领型、开合、纹理、装饰、面料垂感等信息。当前不能仅靠这些代理指标判断两件服装款式相同。

## 四、服装设计视角：人格一致不应变成服装雷同

以下是**看图后、已知标签的定性判断**，不是独立人格准确率。

| 人格 | 当前可保留的线索 | 应调整的边界与变化方向 |
|---|---|---|
| MUTE | 哑光感、简洁基础、克制色彩 | 保留安静，不必靠加亮色制造差异；增加衬衫/短袖/长外层/裙装之间的比例变化 |
| ICED | 冷浅色、轻薄表面、收净轮廓 | 同色可以成立，但不能连续六张都像浅蓝上衣配宽裤；以利落短外套、窄裙、连衣装形成轮廓差 |
| HEIR | 海军蓝、米色、经典外层 | `master_23_v1` 的蝴蝶结装饰与包鞋语气需复审，避免把老钱剪裁变成宫廷拼搭 |
| EASE | 宽松衬衫、轻松裤装、自然浅色 | 首屏 `master_18` 的贴身半透明上装、部分强结构外层偏离松弛感；变化应靠材质和轻重比例 |
| MELT | 柔粉、奶油色、软圆轮廓 | `master_25_v1` 的束身碎花裙更接近戏剧浪漫；补低装饰针织、软裤和简洁裙装 |
| WABI | 自然肌理、低彩度、留白 | 首屏叠穿和深色吊带裙与VOID明显交叠；用材质秩序区分，而不是增加做旧程度 |
| FLOU | 流动花纹、薄软层次、柔和色 | 轻透上装复用频繁；用斜裁、长短层次、裙裤转换丰富，不靠同款反复换包 |
| NEON | 高彩、显眼主角 | 首屏几套多件高彩拼接同时争抢注意力；一个强主角加支撑款，比每件都抢眼更可读 |
| EDGE | 甜与硬的对比 | 束身、拼接和高彩结构与NEON/OOPS混同；增加日常牛仔、工装等低强度支撑 |
| BOLT | 戏剧感、精致装饰 | `master_30 / master_30_v1` 的整身宫廷感强，适合主题层级而非默认日常；加强精简版本 |
| FILM | 复古灰褐、旧感表面 | 多件拼布/破坏型裙裤与WABI/VOID难区分；需要时代剪裁和配件锚点，不只是“旧” |
| JADE | 浅色、交叠、立领/东方装饰 | 同裤同包占比过高；用交叠裙、长外层、窄长裙、干净裤装的切换保留东方语汇 |
| LOOP | 可复用基础与模块线索 | 现状更像反复出现同一牛仔裤，不等于模块化；应呈现可见的长度、层数和场景转换 |
| NOIR | 深色、冷静线条 | 首屏部分层叠装饰裙偏EDGE，白纹样衬衫也弱化肃杀感；补有力长外层和窄长比例 |
| VOID | 松软包裹、低彩度、状态感 | 首屏深色吊带裙本身未必能独立读出VOID；应通过松紧错位、层次和材质增强辨识 |
| OOPS | 冲突和反常规结构 | 首屏近似“多套高彩拼布制服”；应加入比例、正式/休闲、材质的受控冲突，而非只换荧光块 |

### 不同人格没有重复穿搭 ID，也可能让人感觉一样

正式冷启动的各人格首 10 条之间，没有相同穿搭 ID；但首 10 条的**独立主角单品**仍存在这些交叉：

- WABI 与 VOID 共享 4 件主角，包含两件 VOID 连衣裙和两件 VOID 上装。
- NEON 与 EDGE 共享 4 件主角，包含高彩拼接上装。
- MELT 与 FLOU 共享 3 件主角。
- EDGE 与 OOPS 共享 3 件主角。

共享基础款是合理的；反复共享承担人格识别任务的高辨识主角，则需要检查人格边界和成套表达是否真正不同。

## 五、不同单品 ID 的近似款审计

全库筛查结果：同品类轮廓近似 2,027 对；同品类平均颜色接近 4,154 对；同时满足本次轮廓与颜色阈值的 **443 对，涉及 278 个单品 ID**。

443 对的品类分布：上装176、裤装119、半裙72、外套47、鞋14、帽8、连衣裙4、包3。它们是复核候选，不是443件重复衣服，更不是443套应下架的穿搭。

### 视觉确认的高近似候选

| 单品对 | 观察 | 建议 |
|---|---|---|
| `heir_skirt_0435` / `heir_skirt_0579` | 同为深蓝腰带百褶裙，轮廓、长度和色感接近 | 归入同款式家族；默认推荐中不要相邻出现 |
| `ease_top_0324` / `ease_top_0564` | 米色翻领衬衫、卷袖、胸袋和松量十分相近 | 保留较优资产作默认款，另一件作为细节版本候选 |
| `iced_bottom_0402` / `iced_bottom_0418` | 浅蓝高腰长裤，裤管宽度略有区别，但缩略图体感接近 | 同一推荐组中拉开距离，并搭配明显不同的上身轮廓 |

### 不能机械判重复的反例

- `void_top_0071` 与 `mute_top_0353`：数值接近，但一件是灰色连帽拼接上衣，另一件是印花翻领衬衫，款式明显不同。
- `wabi_skirt_0214` 与 `wabi_skirt_0454`：同灰褐色近似外轮廓，但平整短裙与抽绳褶量裙的结构不同。
- `mute_top_0002` 与 `mute_top_0321`：深色相近，但衬衫开合与垂褶领结构不同。

因此，正式“款式家族”还必须纳入领型、袖型、衣长、开合、褶量、纹理/图案、装饰强度。600件这些语义目前仍待审核，不能靠生产文案补成已验证标签。

## 六、造成雷同的机制

1. **去掉重复 ID，不等于去掉重复体感。**当前滚动分页的排除集只包含 outfit_id；同配方的替换版本与近似单品会继续通过。
2. **排序没有推荐组约束。**当前主 App 按单套得分排序，同分按 outfit_id 排序；`master_03` 与它的 `v1/v2` 很容易相邻。没有连续10条主单品上限，也没有款式家族间隔。
3. **主角指标会掩盖重复底装。**HEIR 首10有10个不同主角仍出现底装重复；JADE 换上衣但裤装不变尤其明显。
4. **季节参数没有真正产生差异。**两种模式下，16个人格的四季前30条排序各自完全相同。前端发送 `spring/summer/autumn/winter`，单品保存“春/夏/秋/冬/四季”；当前函数直接求集合交集，没有归一化。且季节目前是单品标签并集的软加减分，不是整套可穿的硬门槛。
5. **人格标签仍有自我证明风险。**当前加分包含主人格同名 +64、次人格 +28；“呼应你的人格风格”可以仅由同名标签产生。它不是从成套轮廓与材质读出的结论。
6. **全库容量没有完全转化为推荐变化。**仍有89件未被生效配方使用。不能把600个文件直接解释为600种已经被用户看到的设计。

## 七、整改优先级与建议验收标准

### P0：先减少同组雷同，不牺牲人格

- 在召回后增加“成组挑选”步骤：优先保证人格/场景可用，再对同一主衣服、同父配方和高近似组合做间隔。
- 默认首屏6条中，同父配方最多1条；不要连续展示主配方及v1/v2。将近似版本放在详情的“这套的其他变化”，而非都占首页位置。
- 所有连续10条中，同一主服装ID最多2次。库存不足时减少条数或说明候选已看完，不拿不适配的衣服凑满。
- 先处理JADE和LOOP的裤装集中，再处理BOLT/EDGE/FILM；增加裙装、连衣装、外层等现有可用结构的覆盖。
- 统一季节枚举，并把“室内冬装”等例外显式区分。不能只将字符串改成中文就宣称季节适配完成。

### P1：把“近似款”归为可审阅的款式家族

- 审核443对候选，优先上述三组高近似款。记录同款变体、同色异款、相近廓形、明确不同四类关系；不要整批删除。
- 首10条相同款式家族建议最多2条；亲缘配方至少间隔8条。此为待验证产品阈值，不是行业定律。
- 不设置“一刀切的同色上限”。MUTE/ICED/JADE/NOIR可以保持相近色域，但要有可见的衣长、松紧、品类和层次变化。
- 场景允许时，首10条至少覆盖3种主服装结构；若用户明确只看裙装，则在裙长、廓形、袖型、材质表达上变化，不强塞裤装。
- 默认推荐与“一衣多穿/胶囊衣橱”分开：后一模式可以高复用，但应清楚告诉用户这是同件不同穿法。

### P2：建立人格适配的独立验收

- 每人格先审10套锚点，覆盖入门、典型和实验，不把主题/戏剧造型默认放进日常。
- 隐藏人格标签进行Top-2判断，记录廓形、材质、色彩、场景依据与争议。沿用原计划的Top-1≥70%、Top-2≥90%作为未来目标，当前没有数据证明达到。
- 对NEON/EDGE/OOPS、WABI/FILM/VOID、MELT/FLOU做成对边界评审；共享基础款不扣分，共享主角须证明表达差异。
- 用旧/新排序的同等长度盲对照，记录“看起来重复”“愿意继续看”“想试穿”三项；样本数、用户分层和目标提升幅度应在测试前确定。

### 建议的放行清单

1. 人格与场景不因多样性重排而明显偏离。
2. 首屏无父子配方连排；连续10条主服装重复上限通过。
3. 近似款不相邻；同色异款有足够可见差异。
4. 6→12→18等分页交界也纳入窗口检查，不能每页单独合格、跨页仍重复。
5. 换一批与换人格不会把旧请求结果混入；曝光抑制作用于主衣服/款式家族，而非仅整套ID。
6. 所有“人格准确率”“用户喜欢度提升”都有独立数据，不能用标签命中或生成设定替代。
