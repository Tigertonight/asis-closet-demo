# Selfit App 体验承接与前端重构方案

状态：已进入前端实现  
适用入口：`/selfit`、`/selfit/mirror`、`/wearwow/demo`

## 1. 设计目标

Selfit 的体验不是三个独立产品，而是一条连续的自我认识路径：

1. Mirror：看见我，建立仪式感。
2. Selfit：认识我，形成可解释的风格人格。
3. App：记住我，把人格转化成每天可执行的穿搭选择。

App 的核心价值不是展示 AI 能力，而是让用户持续感受到：Selfit 记得我是谁，也能解释每一次推荐为什么适合我。

## 2. 产品角色

### Mirror · 仪式模式

- 单屏、远距离、高辨识行动。
- 使用全屏酒红织物、较大拍照按钮和阶段式识别文案。
- 完成后通过扫码把照片与会话带入 Selfit。

### Selfit · 认识模式

- 以 `suit × like × vibe` 完成风格判断。
- 报告是品牌内容母体，输出人格名称、关键词、推荐色、穿搭原则和灵感证据。
- 报告后增加“用这个风格开始搭配”，把当前人格带入 App。

### App · 行动模式

- 默认浅色、安静、图片优先。
- 首页先显示用户人格，再提供试穿、提取单品、问搭配等行动。
- 所有建议引用同一份人格结果，避免再次询问用户已经回答过的信息。

## 3. 跨端交接协议

### Mirror → Selfit

- 保留现有 handoff token。
- 手机端领取后沿用镜前照片，直接进入未完成的风格步骤。
- 文案明确“刚才镜子里的照片已带入”。

### Selfit → App

- 报告渲染时记录稳定的 `typeId`，只保存人格标识，不在浏览器保存照片或完整报告。
- 报告 CTA 使用 `/wearwow/demo?from=report&persona={typeId}`。
- App 优先复用同域 `selfit.auth.session.v1` 登录态，不要求再次登录。
- 首次从报告进入时展示品牌过渡帧：
  - `我们记住你了`
  - `从认识自己，开始真正适合你的穿搭`
  - 明确显示已经带入的人格名称。
- 用户确认后进入推荐首页，并清理 URL 中的一次性交接参数。

### 回看报告

- 首页人格卡和“我的”页均保留报告入口。
- App 使用同一个人格资源目录，不另外维护一套名称、配色和关键词。

## 4. App 信息架构

底部导航固定为四个用户心智和一个主行动：

1. 推荐：人格、今日推荐、同频灵感。
2. 问搭配：结合人格与衣橱的对话式搭配。
3. 添加：上传、拍照、链接提取。
4. 衣橱：单品与已保存套装。
5. 我的：人格、试穿形象、适配色和用户作品。

避免使用“灵感 / 搭配”两个含义重叠的一级入口。

## 5. 页面与交互规格

### 5.1 跨端过渡帧

- 全屏酒红织物，仅在报告进入 App 时出现。
- 顶部白色 Selfit 字标，中部使用已有蕾丝资产。
- 底部单一白色 CTA“开始搭配”。
- 页面淡入 600ms；减少动效模式下立即呈现。

### 5.2 推荐首页

首屏顺序：

1. Selfit 字标。
2. 用户名与人格名称。
3. 主标题“今天，也穿得更像自己”。
4. 人格卡：官方人格 Hero、人格码、名称、摘要、关键词、五个推荐色。
5. 三个行动：拍一件试试、提取单品、问问搭配。
6. 今日推荐。
7. 与人格同频的真实穿搭灵感。

数据状态：

- 有衣橱套装：今日推荐使用用户真实套装，可进入详情和试穿。
- 无套装：使用当前人格报告中的真实穿搭素材，不构造虚假套装。
- 无人格：回退到完成风格测试的引导，不虚构测试结果。
- 图片失败：显示中性占位和恢复建议，不暴露资源路径。

### 5.3 穿搭详情

- 大图保持视觉主位。
- 下方显示组成单品与当前试穿形象。
- 底部行动调整为“调整搭配 / 生成试穿图”。
- 分享使用统一线性图标，优先调用系统分享能力。

### 5.4 试穿

- 结果图占据页面最大面积。
- 生成态使用品牌酒红浮层、既有 Lottie 和用户语言。
- 生成成功：换一套、重新生成、收藏。
- 可恢复失败：提示更换清楚照片或减少遮挡。
- 取消仅停止当前界面等待，不删除已保存的套装。

### 5.5 添加与提取单品

统一为底部操作层：

- 从相册选择：单品图或整套穿搭图。
- 现在拍一张：强调简单背景和完整衣物。
- 从链接提取：小红书或普通网页链接。

状态文案依次为：读取内容、识别衣服、整理图片、已放入衣橱。失败时给出“改用截图或上传图片”的下一步。

### 5.6 问搭配

- 首屏问题是“今天想以什么样子出现？”，不展示技术能力列表。
- 快捷问题来自用户场景。
- 请求上下文附带当前 `typeId`、人格关键词、推荐色、衣橱数量和最近会话。
- AI 的理由必须连接到用户人格或已有衣物，避免只输出泛化穿搭建议。

### 5.7 衣橱

- 一级只保留单品 / 套装。
- 分类横向滚动，计数作为辅助信息。
- 单品卡以抠图为主，行动为“去搭配”。
- 空状态直接引导上传或链接提取。
- “开始搭配”是浮动主行动，不再使用含义宽泛的“自由搭配”。

### 5.8 我的

- 用户信息后第一块是人格资产，不是订阅广告。
- 移除首屏 `selfit PRO` 推销卡。
- 人格卡下显示试穿形象与推荐色。
- 内容区保留试穿记录、我的作品和收藏。
- 商业化入口应在用户已经获得价值后出现，不抢占人格资产的位置。

## 6. 视觉系统

- 画布：`#FAFAFA`
- 表面：`#FFFFFF`
- 品牌：`#8A011B`
- 按下：`#720015`
- 正文：`#222222`
- 次级文字：`#666666`
- 弱文字：`#999999`
- 分隔线：`#E7E7E7`
- 媒体圆角：8px
- 卡片圆角：12px
- 行动圆角：18px
- 页面动效：240ms
- 跨端人格揭示：600ms

官方人格 Hero、字标、蕾丝、织物和报告灵感资产直接复用，不在 App 中重画。

## 7. 文案原则

- 说用户要完成的事情：`生成试穿图`，不说模型或流水线。
- 解释推荐与用户的关系：`根据你的冷感冰面`，不说置信度。
- 失败文案给出下一步：`换一张自然光、衣服完整的照片再试`。
- 中文与 `selfit` 之间保留空格。
- 导航不使用抽象、重叠或 Demo 命名。

## 8. 验收标准

- 从报告进入 App 不需要重复登录。
- App 显示的人格名称、关键词、色板和报告一致。
- 390、393、430px 无水平溢出。
- 桌面只居中显示移动端壳，不展开为后台布局。
- 首屏可理解“我是谁”和下一步能做什么。
- 上传、提取、生成、成功、重试和失败均有用户态文案。
- 图标使用统一 SVG 线性语言，不混用 Unicode 功能符号。
- 浏览器无运行时错误和新增损坏资源。
- 后端衣橱、搭配、试穿和会话能力保持可用。
