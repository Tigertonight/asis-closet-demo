保留稳定对象 URL 供追溯，不复制临时签名到业务数据。

`outputs/inspiration-delivery/20260909/`。

## 页面与试穿

`GET /selfit/try-on/inspiration-topics` 需要登录或访客会话，无需完成风格测试。
返回 4 个主题及完整的结构化穿搭；素材未完成校验时返回可重试错误。
灵感库将这 16 套穿搭作为普通卡片与其他内容同级展示，不再显示四个主题合集入口。
每张卡片可查看单品、收藏和试穿；主题归类仍保留在素材数据中。
主题请求失败保留已显示内容，推荐分页不重复插入这 16 套穿搭。

沿用结构化拆款的 ID 与接口约定，模板命名空间为 `inspiration_commute` 等，
因此穿搭 ID 形如 `report_inspiration_commute_outfits-01_<版本哈希>`。
这里的 `report_` 是兼容已有详情、收藏和试穿入口的技术前缀，并非人格分类；
`primary_persona` 为 `null`。人格报告、默认人格笔记抽样和已有试穿示例维持原目录。

试穿读取原穿搭照片、所选模特照片和全部透明单品，沿用项目的穿法、开合、遮挡和叠穿逻辑。
这批新穿搭没有既有试穿示例，按原有实时生成流程执行。
浏览或试穿不会把素材自动加入个人衣橱；只有用户收藏／保存时才复制所需记录。

## 导入校验

`scripts/register_inspiration_delivery.py --batch outputs/inspiration-delivery/20260909`
在启用业务清单前检查：

1. 每个主题 4 套、源图片无遗漏、单品 ID／配对／层次顺序完整。
2. 透明 PNG 尺寸与 RGB 未变，源图和结果哈希与抠图记录一致。
3. 每张最终图片的目检结论绑定到该结果的 SHA-256。
4. 原图和最终 PNG 已在七牛登记，远程回读字节、大小和对象位置一致。

全部通过后先写来源／抠图映射，最后原子替换灵感库清单。
PNG 二进制不进入 Git；本地数据接入不等于服务器发布。
