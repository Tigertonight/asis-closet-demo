# 用户参考图库：拆款与风格映射完成度核验

核验日期：2026-09-03。本报告评价附件图库的使用情况，不将原创 V2 的资产数量视作附件拆款完成数量。

## 已核实

- `图库总表 穿搭标签版.xlsx` 的 366 条记录已导入 `reference-looks.internal.json`。本次逐一比对 `图片.zip`：366 条有标签图片和 11 张待标注图片，377/377 文件摘要匹配。
- 人格、次人格、地域、体型和结构标签来自表格列的转换，见 `scripts/import_selfit_reference_library.py`。这一步不是模型看图后重新判型。
- 366 个记录 ID / 文件名唯一，但只有 365 个不同图片摘要。`0007_6a86467b0000000038001f45_05.jpg` 和 `0057_6a86467b0000000038001f45_05.jpg` 内容相同，需要在训练/评估与参考采样中去重。
- 原图保持 `source_recorded`、`publishable:false`，11 张额外图片保持 `unlabeled`，未将其作为正式原创资产直接发布。
- 但“内部清单”目前存放在公开静态目录：本地未登录请求 `/static/selfit/data/reference-looks.internal.json` 返回 200。元数据隔离只是字段声明，不是访问控制；应迁出静态目录或增加鉴权。本次未核实线上是否同样暴露。
- V2 的 600 件单品均声明为 `generated_original`。其中 526 件带 `production.reference_ids`，但仅关联 11 张不同参考图，覆盖 366 条参考记录的约 3%。同一参考图最多挂在 76 件单品上。
- `scripts/build_selfit_content_expansion.py` 按人格/次人格建立索引，再取该人格的首个参考 ID；LOOP / OOPS 不取参考 ID。该关联是生产元数据，不能证明实际调用图像分析或逐件拆款。
- 1,200 套配方没有直接的 `reference_ids` / `extraction_job_id` / `source_reference_id` 字段；可通过单品反查有限的参考关联，但未找到该批图库逐图的拆款规格、mask、单品输出和图片级人格校验报告。

## 评价

资料入库基本完成，但仍有重复图需要治理。若目标是“逐张参考图 → 结构化拆款 → 单品规格 → 原创生成 → 人格映射验证”，当前尚未形成可验收闭环，不能称为完成 366 张拆款。

原始样本分布也严重不均：EASE 126、FLOU 59、EDGE 49，合计 234/366；NOIR / VOID 各 1，LOOP / OOPS 为 0。原始标签不能未经分层审查就作为 16 人格映射准确率的评价集。

## 建议实施顺序（本次只评价，未执行新一轮拆款）

1. 先将内部清单移出公开静态目录；对重复图建立别名，补标 11 张，按人格与结构维度建立代表性样本清单。
2. 先做分层样本试跑，保存 `reference_id → extraction_job_id → 单品类别/轮廓/层级/颜色/材质/结构 → 人工复核`，原图和拆款图仍仅供内部研究。
3. 根据真实拆款规格设计原创单品，记录生成任务与参考证据，禁止只挂参考 ID。
4. 用独立、去重的留出集做人格 Top-1 / Top-2 与结构映射评价，分别报告机器判断、表格标签和人工判定，避免自我验证。
5. 通过上述样本验收后扩展到全量，再讨论能否称为完成图库到内容池的生产闭环。
