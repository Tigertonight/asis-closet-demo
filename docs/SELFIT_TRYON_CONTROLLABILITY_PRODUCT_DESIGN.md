# selfit「可控试穿」P0 产品与设计方案

> 版本：V1.0
> 日期：2026-09-02
> 状态：产品与视觉方案，可进入交互评审和技术拆解
> 范围：App 内从穿搭详情进入试穿，到生成结果复核的完整链路

## 1. 一句话定义

把试穿从一次不可解释的“黑盒出图”，升级为一个用户始终知道 **会替换什么、为什么没替换、哪里需要检查、怎样只修一件** 的穿搭判断工具。

本次设计优先服务一个核心判断：

> 这套衣服穿在我身上，整体是否适合我？

技术状态、mask、模型、provider 和流水线信息不进入主界面。

---

## 2. 为什么这是第一优先级

当前链路已经能从套装、本人照片和预设模特进入整套试穿，也已经具备“只替换照片中可见部位”的基础能力。但产品层仍有四个关键断点：

1. **生成前不可预期**：用户不知道帽子、包、裙子、鞋等哪些会被替换。
2. **生成后不可解释**：没替换时，用户不知道是未入镜、遮挡、识别失败还是系统遗漏。
3. **结果不可局部修正**：一件单品有问题，只能整张重新生成，时间和结果都不可控。
4. **照片适配提示过晚**：直到生成失败，用户才知道照片不适合某件单品。

这四点直接影响试穿能力的可信度。对 selfit 来说，可信度比“看起来像 AI”更重要。

### P0 成功标准

- 用户在生成前能准确复述本次预计替换的单品。
- 用户在生成后能看懂每件单品的处理结果。
- 单件异常无需重新选择整套穿搭即可修正。
- “未替换”不再被理解为系统失效。

---

## 3. 产品目标与边界

### 3.1 本期目标

- 提供生成前的「替换确认」。
- 允许用户按单品开启或关闭替换。
- 根据当前人物照片，预判各单品的可见性与可替换性。
- 生成后展示单品级结果状态和原因。
- 支持针对单件单品的重新生成。
- 保留更换照片、调整搭配、整套重试入口。

### 3.2 本期不做

- 不提供专业级 mask 涂抹或身体区域编辑。
- 不承诺补全原照片未拍到的身体部位。
- 不把用户照片强制裁成全身构图。
- 不提供面料物理模拟、尺码预测或真实合身度承诺。
- 不在主流程展示置信度百分比、人体解析框或算法日志。

### 3.3 核心原则

1. **所见即可换**：只替换原照片中真实可见、可定位的部位。
2. **用户有最终决定权**：系统预选，用户可关闭；系统不可替换的项需说明原因。
3. **先解释，再行动**：任何不可替换和需要复核状态都附带下一步建议。
4. **局部问题局部处理**：单件失败不迫使用户重做整条链路。
5. **图片是主角**：视觉上先看本人和穿搭，状态说明退居第二层。

---

## 4. 核心用户故事

### 主路径

> 我从推荐或衣橱选中一套穿搭，想先确认哪些单品能穿到我的照片上，再生成一张可信的试穿图。

### 补充路径

- 作为只露出上半身的用户，我希望能试穿上衣、帽子或可见的包，不因没有露出腿脚而被阻止。
- 作为对配饰不确定的用户，我希望关闭包或帽子，只试衣服。
- 作为生成后发现裙子边缘异常的用户，我希望只修裙子，不重新选择照片和整套搭配。
- 作为使用多张本人照片的用户，我希望知道哪张照片更适合当前这套单品。
- 作为结果被遮挡的用户，我希望知道某件单品为什么没有替换，以及更换怎样的照片能解决。

## 5. 端到端流程

```text
穿搭详情
  ↓ 点击「开始试穿」
替换确认
  ├─ 系统判断当前照片可见区域
  ├─ 预选可替换单品
  ├─ 用户开关单品 / 更换照片
  └─ 确认「生成试穿图（N 件）」
  ↓
生成中
  ├─ 展示正在处理的单品与阶段
  ├─ 可返回 App 继续浏览
  └─ 任务完成后恢复结果
  ↓
试穿结果
  ├─ 结果图为视觉中心
  ├─ 显示已替换 / 检查一下 / 未替换
  ├─ 单件重试或更换照片
  └─ 收藏 / 分享 / 换一套
```

### 5.1 入口调整

穿搭详情页底部主按钮由「生成试穿图」改为 **「开始试穿」**。

原因：点击后先进入确认，而不是立即消耗一次生成任务。按钮命名必须与实际行为一致。

单品详情页：

- 上衣、下装、半裙、连衣装：`试穿这件`
- 帽子、包、鞋、配饰：`加入试穿搭配`
- 点击后统一进入替换确认页，不走另一套预览模式。

### 5.2 替换确认页

这是本次 P0 的核心新增页面，而不是临时弹窗。

页面结构：

1. 顶部导航：返回 / `确认试穿`
2. 人物照片预览：使用当前本人照片或预设模特
3. 照片状态行：`当前照片 · 上半身清楚` + `更换`
4. 本次替换摘要：`预计替换 3 件单品`
5. 单品列表：缩略图、名称、状态、开关或建议
6. 底部固定 CTA：`生成试穿图（3 件）`

#### 单品状态

| 状态 | UI 表现 | 是否可操作 | 示例文案 |
|---|---|---:|---|
| 可替换 | 默认开启的 wine 开关 | 是 | `画面中清楚可见` |
| 用户关闭 | 关闭的中性开关 | 是 | `本次保留原穿搭` |
| 部分遮挡 | 默认开启，附提示 | 是 | `包带被手臂遮住，生成后请检查边缘` |
| 未入镜 | 灰色状态，无开关 | 否 | `照片没有拍到脚部，本次跳过鞋子` |
| 无法定位 | 灰色状态，提供换照片 | 否 | `下装区域被遮挡，换一张站立照会更完整` |
| 类目冲突 | 保留一个主项，其他关闭 | 是 | `半裙与长裤占用同一区域，请选择一件` |

#### 可见性规则

系统按单品判断，不再要求照片同时露出全部身体部位。

| 单品 | 最低可见条件 | 默认行为 |
|---|---|---|
| 帽子 | 头部和发际区域清楚 | 可替换 |
| 上衣 / 外套 | 肩部、躯干主要区域清楚 | 可替换 |
| 包 | 包所在侧身体或手持区域可见 | 可替换；遮挡时提示复核 |
| 下装 / 半裙 | 腰线至主要下摆区域可见 | 可替换 |
| 连衣装 | 肩部至裙摆主要区域可见 | 可替换；与上衣/下装冲突 |
| 鞋 | 双脚或至少目标脚部清楚 | 可替换；未入镜自动跳过 |
| 围巾 / 首饰 | 对应颈部或局部清楚 | 可替换；小面积配饰提示复核 |

系统不得为了替换鞋、包或裙子而扩展画面、补造身体或改变人物构图。

#### 选择逻辑

- 可替换项默认开启。
- 部分遮挡项默认开启，但使用柔和提示，不弹阻断框。
- 未入镜项自动跳过，不计入 CTA 数量。
- 至少开启 1 件单品才允许生成。
- 用户关闭某项后，在本次试穿任务内记住选择。
- 互斥槽位如 `连衣装` 与 `上衣 + 下装` 同时存在时，要求用户二选一；不由系统静默决定。

### 5.3 生成中

沿用 onboarding loading 页的品牌语言：暖白空间、酒红 textile/刺绣装饰、独立的 `selfit` 标识，避免大块实心红色技术面板。

信息层级：

1. 品牌动效或分阶段装饰图
2. 主文案：`正在把这 3 件穿到你身上`
3. 当前阶段：`先处理上衣和裙子的轮廓`
4. 已选单品的小缩略图列
5. 进度与弱操作：`返回继续逛`

建议阶段文案：

- 8%：`正在确认照片与单品`
- 28%：`先处理衣服的轮廓`
- 55%：`正在保留你的身形和姿态`
- 78%：`整理包、帽子和衣服边缘`
- 94%：`再看一遍整体是否自然`

交互约束：

- 返回不等于取消任务；返回后用轻量状态条提示 `试穿图生成中`。
- 如后端暂不支持真正取消，不出现“取消生成”；改用 `返回继续逛`。
- 同一人物照片 + 同一套装 + 同一替换选择，重复点击应恢复已有任务或结果。

### 5.4 结果页

首屏 70% 以上视觉面积留给试穿结果，结果图不得被大段说明压缩。

页面结构：

1. 顶部：返回 / `试穿` / 收藏
2. 结果图 Hero
3. 轻量对比操作：按住 `看原图`
4. 摘要：`已替换 3 件 · 1 处建议检查`
5. 单品结果列表
6. 固定行动：`调整搭配` / `保存结果`

#### 结果状态

| 状态 | 标签 | 说明 | 主行动 |
|---|---|---|---|
| applied | `已替换` | 该单品已纳入最终结果 | 无 |
| review | `检查一下` | 结果可看，但边缘、遮挡或细节不够稳定 | `重新处理这件` |
| skipped_not_visible | `未入镜` | 原照片没有对应区域 | `更换照片` |
| skipped_user | `已保留` | 用户在生成前关闭了替换 | `下次开启` |
| failed_item | `未替换` | 单件处理失败，其余结果保留 | `重新处理这件` |

禁止只显示笼统的 `生成成功`。成功信息必须包含本次实际应用的单品数量。

#### 单件重试

点击 `重新处理这件` 后打开底部抽屉：

- 展示当前结果局部预览与目标单品。
- 默认选项：`保持其他部分不变`。
- 可选原因：`版型不对 / 颜色不对 / 图案丢失 / 边缘不自然 / 没有换上`。
- 主行动：`重新处理这件`。
- 完成后产生一个新版本，可在新旧结果之间切换；不覆盖上一版。

产品语义上是“单件重试”。技术上即使仍需重新生成整张图，也必须把约束限定为目标单品，并尽量锁定人物、背景和其他已通过单品。

### 5.5 更换照片

照片选择抽屉只展示：

- 当前本人照片
- onboarding 上传的全身照
- 用户后续保存的照片
- 预设模特（明确标记 `预设模特`）

每张照片显示与当前试穿的适配摘要：

- `适合这套 · 可替换 4 件`
- `适合上半身 · 鞋子未入镜`
- `遮挡较多 · 建议换一张`

不使用“照片不合格”这种笼统否定。说明哪一件受影响以及怎样改善。

## 7. 视觉方案

### 7.1 Design DNA

#### Design system：可量化规则

- 画布：`#FAFAFA`
- 主表面：`#FFFFFF`
- 品牌与主行动：`#8A011B`
- 按下态：`#720015`
- 主文字：`#222222`
- 次文字：`#666666`
- 辅助文字：`#999999`
- 分割线：`#E7E7E7`
- 温和状态底：`#F7F1F2`
- 警示状态底：`#F8F3EC`，文字使用深棕，不使用高饱和橙色
- 页面横边距：`24px`；正文严格信息块可使用 `32px`
- 主按钮：高 `44px`、圆角 `18px`
- 列表卡：圆角 `12px`，1px 浅灰线；仅浮层使用柔和阴影
- 图片：`8px` 圆角，固定比例，优先 `object-fit: cover`
- 最小可点区域：`44 × 44px`

#### Design style：感受规则

- 关键词：可信、安静、个人化、编辑感、轻复古。
- 页面像一本替用户整理选择的私人穿搭册，而不是 AI 控制台。
- 单品状态通过层级、短文案和轻量标签表达，不堆叠彩色徽章。
- 酒红只用于主 CTA、选中态、关键数量和品牌装饰。
- 图片区域保持干净；不在人物身上覆盖识别框、热区或技术蒙层。

#### Visual effects：动效规则

- 不引入 WebGL、粒子或炫技 3D 效果。
- 使用现有 onboarding 刺绣/镜面资产和轻量 CSS 过渡。
- 页面进入：`220ms`，`cubic-bezier(.2,.8,.2,1)`。
- 单品开关：`160ms`；状态改变只做淡入与轻微位移，不弹跳。
- 结果出现：图片由 `opacity: 0` 到 `1`，时长 `320ms`。
- `prefers-reduced-motion` 下取消位移与循环动效，仅保留即时淡入。

### 7.2 视觉层级

1. **第一层：人物与结果图**——用户首先看“像不像我、适不适合”。
2. **第二层：替换摘要**——一句话告诉用户换了几件、哪里要检查。
3. **第三层：单品状态**——需要时才逐件展开。
4. **第四层：解释和建议**——只在异常项出现，避免正常状态噪音。

### 7.3 组件规范

#### 单品替换行 `TryOnPieceRow`

- 高度：正常态最小 `72px`；有说明时 `88px`。
- 左侧：`52 × 52px` 单品图，白底，`object-fit: contain`。
- 中部：14px medium 名称 + 14px secondary 状态说明。
- 右侧：开关、状态文本或 44px 文本按钮，三者只出现一种。
- 行间只使用分割线，不做独立悬浮卡片。

#### 状态标签 `PieceStatus`

- `已替换`：酒红文字，无实心底。
- `检查一下`：深棕文字 + 暖米色浅底。
- `未入镜 / 已保留`：灰色文字。
- 不使用红色感叹号表示非错误状态。

#### 照片适配条 `PhotoFitBar`

- 白色表面、12px 圆角、单行摘要。
- 左侧 36px 圆形或圆角矩形照片缩略图。
- 中部：当前照片 + 适配摘要。
- 右侧：`更换`，酒红文本按钮，命中区域 44px。

#### 底部行动栏

- 暖白半透明背景 + 顶部分割线，适配 safe area。
- 单主行动时宽 `313px` 居中。
- 双行动时，次按钮白底酒红边框，主按钮酒红底白字。
- CTA 文案包含明确结果：`生成试穿图（3 件）`，不写模糊的 `下一步`。

## 8. 信息与文案规范

### 推荐文案

- `预计替换 3 件单品`
- `照片没有拍到脚部，本次会跳过鞋子`
- `包带被手臂遮住，生成后建议检查边缘`
- `已替换画面中可见的 3 件单品`
- `这件没有换好，可以只重新处理这一件`
- `换一张露出下半身的照片，就可以继续试裙子和鞋`

### 禁止文案

- `人体解析失败`
- `mask 置信度不足`
- `provider 超时`
- `invalid lower body region`
- `生成失败，请重试`（没有原因和下一步）
- `照片不合格`（没有指出受影响的单品）

### 试穿真实性声明

在首次结果页底部以弱信息说明：

> 试穿图用于判断颜色、比例和整体风格，实际尺码与面料效果请以实物为准。

只在首次或帮助页完整展示，后续不反复打扰。

## 9. 状态模型

```text
idle
  → analyzing_photo
  → confirmation_ready
      ├─ needs_choice（互斥单品待选择）
      ├─ no_replaceable_item（当前照片无可替换项）
      └─ ready_to_generate
  → queued
  → processing
      ├─ completed
      ├─ completed_with_review
      ├─ recoverable_failure
      └─ terminal_failure
  → item_retrying
  → completed_new_version
```

关键要求：

- 页面刷新后可根据 `job_id` 恢复 queued / processing 状态。
- 返回上一页不改变任务状态。
- 每个结果保留 `version_id`，单件重试生成新版本。
- 列表记录显示最终摘要，如 `3 件已替换 · 1 件未入镜`。

## 11. 埋点与衡量

### 核心漏斗

1. `tryon_confirmation_view`
2. `tryon_piece_toggle`
3. `tryon_generate_submit`
4. `tryon_result_view`
5. `tryon_piece_retry`
6. `tryon_result_save`
7. `tryon_result_share`

### 关键指标

- 确认页 → 生成提交率
- 生成结果可展示率
- 单件状态解释展开率
- 单件重试率与重试成功率
- 整套重试率（目标是明显下降）
- 结果保存率、分享率
- 因照片问题退出率
- 用户关闭配饰/单品的比例

### 建议目标

- 80% 以上用户在 10 秒内完成替换确认。
- “为什么没换上”的用户反馈降低 50%。
- 有局部异常时，单件重试占所有重试的 60% 以上。
- 生成后保存或分享率较当前提升 20%。

## 12. P0 研发拆分

### P0-A：可解释的替换确认

- 新增 preview-plan 能力。
- 新增确认页及单品开关。
- 按可见部位逐件判定。
- 处理连衣装与上下装冲突。
- 创建任务时传 selected_item_ids。

### P0-B：单品级结果

- 结果回传 piece_results。
- 结果页展示已替换、检查一下、未入镜和已保留。
- 列表记录保存摘要。

### P0-C：单件重试

- 新增单件重试接口和版本模型。
- 提供问题原因选择。
- 默认锁定人物、背景和其他单品。
- 支持新旧版本回看。

### P0-D：任务恢复

- 退出结果页后任务继续。
- App 内展示轻量生成状态。
- 返回后恢复任务或结果。
- 使用 client_request_id 防止重复提交。

## 13. 验收标准

### 功能验收

- 半身照只露上身时，上衣可选，鞋自动标记未入镜，生成按钮可用。
- 用户可关闭帽子或包，结果中显示 `已保留`。
- 连衣装与上衣/下装冲突时，系统要求用户选择方案。
- 生成结果明确显示实际应用和跳过的单品。
- 单件重试不需要重新选择照片和套装。
- 返回首页再进入时，进行中的任务可恢复。
- 相同请求不会创建重复任务。

### 视觉验收

- 390、393、430px 宽度无横向滚动。
- 桌面端保持 393px 居中 App shell。
- 结果图是首屏视觉中心，操作控件不遮挡主体。
- 所有交互命中区域不小于 44px。
- 正文、标签和按钮没有低于规范的非元数据小字。
- 只使用 `DESIGN.md` 的酒红、暖白、中性色和既有品牌资产。
- 不出现技术词、黑色沉浸弹层、强阴影或多套预览样式。
- reduced motion 下不播放循环动效。

### 易用性验收任务

邀请 5 名非项目成员完成以下任务，不给予解释：

1. 用一张半身照试穿上衣和包，关闭帽子。
2. 说出为什么鞋没有出现在结果中。
3. 只重新处理裙子边缘。
4. 返回首页后再次找到仍在生成的任务。

至少 4/5 用户无需提示即可完成，且能正确解释未替换原因。

## 14. 推荐实施顺序

### 第 1 周：确认与解释

- preview-plan 数据结构

- 单件重试

### 上线策略

- 先对内部账号和 10% Demo 用户开放。
- 重点观察 `未入镜` 是否被理解、单件重试是否真正减少整套重试。
- 若局部重试暂时不能稳定锁定其他区域，保留交互入口但标记实验状态，不对全量用户承诺“其他部分完全不变”。

## 15. 设计结论

这次升级不应被理解为“给试穿多加一个设置页”，而是重新定义试穿的信任机制：

- 生成前，用户知道系统准备做什么。
- 生成中，用户知道任务仍在继续。
- 生成后，用户知道系统实际做了什么。
- 局部不满意时，用户能只修改那一件。

这才会让 selfit 的试穿从一个演示能力，变成用户愿意反复使用的穿搭决策工具。
