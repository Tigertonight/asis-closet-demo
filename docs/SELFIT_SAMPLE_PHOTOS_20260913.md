# 内置示例照片优化

四张原图继续使用 `app/static/selfit/assets/samples/` 中的现有文件。前端点击“使用示例照片”后只发送示例编号，服务器直接读取原字节，复用上传接口的检测、照片资产保存、用户索引、手动修正及响应逻辑。

## 接口

- `POST /api/v1/selfit/sessions/{id}/photos/{kind}/sample`，JSON 为 `{"sampleId":"female-face"}`；另三个编号为 `female-body`、`male-face`、`male-body`。
- 校验会话归属、已选性别、照片类型及固定编号，不接受外部 URL 或本地路径。返回结构沿用上传接口的 `photo` / `analysis` / `revision`。
- 幂等键限定在当前会话、照片类型、入口和性别选择版本内。分析前记录当前请求标识，完成后读取最新会话再合并；旧请求返回 `photo.superseded`，不能覆盖新照片或性别。
- `GET /api/v1/selfit/sample-photos/{sampleId}/preview` 返回最高 720×960 的 WebP，支持 ETag 重验证。该公开接口只提供内置示例预览。
- 已有受会话权限保护的照片标记预览接口复用示例缓存。`GET .../suit` 增加 `samplePhotos` 编号映射，便于恢复页面状态。

## 缓存与资产

- `app/selfit_samples.py` 管理固定清单。原图保持字节一致，分析仍由现有真实算法完成，人体分析不使用展示缩图。
- 可删除的派生缓存位于被 Git 忽略的 `outputs/selfit-samples/`，包括真实分析 JSON、普通预览、分析标记图。
- 分析缓存身份包括原图 SHA、照片算法版本、算法源代码、模型权重和依赖版本。代码/权重指纹在进程启动时固定，避免发布期间旧进程将旧结果写入新版本缓存；部署重启后采用新指纹。标记图另含绘图实现指纹。
- 每张样例的并发首次计算在进程内合并，缓存原子写入。未通过的检测不缓存，调试 inspector 不读取或写入真实结果缓存。
- 会话使用现有按字节哈希命名的原图资产，跨会话目录保持独立，历史照片及报告仍可读取。照片索引记录 `source=sample`、编号及指纹；示例不再重复归档为用户上传的 QA 照片。
- 更换性别只清除当前会话中不匹配的示例选择及相关手动值，保留原图文件、个人上传照片和历史报告。

## 预热与发布

运行 `.venv/bin/python scripts/warm_selfit_samples.py` 可预计算四张示例的分析与预览。唯一发布入口 `scripts/deploy_release.sh` 已接入预热步骤；预热失败会保留按需计算和重试能力。缓存不需要上传或提交。

## 验证

- 四张原图与分析输入逐像素一致；缓存结果与真实算法结果一致；验证独立会话、幂等、权限、性别/编号校验、并发面部/全身照和旧请求丢弃。
- 浏览器运行在独立会话/照片目录中；验证 390px、430px、1440px，普通流程无资源错误或溢出。失败重试及延迟返回时切换性别通过。
- 预览大小：女性面部 74,190 B、女性全身 28,168 B、男性面部 41,846 B、男性全身 66,134 B。浏览器不再下载原图或发送示例文件上传。
- 本地缓存命中时，两张示例选择至结果展示约 0.8–1.4 秒；这不是公网或冷启动耗时承诺。
- 复现脚本、页面截图及网络检查结果位于 `outputs/qa/selfit-samples-20260913/`，不进入 Git。
