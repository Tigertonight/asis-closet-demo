## 服务器运行时原图（2026-09-13）

新预设仍要求传入照片与生成时原图的 SHA-256 完全一致。服务器需要使用相同的三张原图；它们作为 `outputs/runtime/` 下的运行时数据提供，不加入 Git，也不上传对象存储。Git 中仅保存 `app/data/female-nano-models.v1.json` 的尺寸、身份及哈希清单。

将已授权的三张原图传入服务器数据目录并校验哈希后，用已推送版本的脚本生成独立、不可覆盖的模特目录：

```bash
.venv/bin/python scripts/prepare_runtime_tryon_models.py \
  --originals outputs/runtime/female-model-originals
```

脚本核对三张原图的身份、哈希和尺寸，同时保留共享清单中的其他模特。输出目录名由清单及全部本地图片哈希决定；已有目录若发生内容漂移会拒绝复用。不要修改 Git 中的共享模特 PNG 或 `manifest.json`。

将脚本返回的绝对路径配置为 `SELFIT_TRYON_MODEL_DIR`。模型列表、同源原图、WebP 预览和试穿匹配会共同使用该目录；没有设置此变量的环境沿用共享目录。生产环境切换前备份原配置并记录旧值，回滚时恢复旧值。代码发布仍只使用服务器上的 `sudo bash scripts/deploy_release.sh <已推送提交>`。

发布后除核对 `/health` 的提交指纹外，还须检查模特列表中的三个尺寸、同源原图 SHA-256、预览的 `image/webp` MIME，并以运行时原图核验预设命中。个人照片和不同照片不得命中这些固定模特预设。

完整批次发布时还需预热全部 288 张女模特 WebP 结果，避免尚未浏览的结果在临时 URL 到期后无法首次下载。先同步已刷新签名的运行时素材库，再运行：

```bash
.venv/bin/python scripts/warm_female_preset_previews.py \
  --registry /绝对路径/运行时素材库.json
```

该步骤只下载已上传、已验收且绑定一致的 WebP，逐张复核缓存 SHA-256，不调用生图接口、不修改预设或男模特数据。存在缺项、错误绑定或损坏缓存时返回失败；发布验证须确认 `cachedPreviews: 288`。已有有效缓存会直接复用，预设匹配和素材展示可在签名到期后继续使用这些本地字节。
