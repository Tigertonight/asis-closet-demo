# 报告配置后台：身材与性别版本

`/report-builder` 使用浏览器 localStorage 保存草稿，导出 JSON 后人工合入产品模板库。“保存成功”仅表示后台本地保存，不代表发布或用户端生效。

当前范围仅为后台模板管理；前置流程、资料接口、人格算法和用户端报告加载逻辑保持不变。

- 16 个人格的 `code` / `masterData.typeId` 保持不变。
- `bodyProfile`：`standard`（通用，旧数据默认值）或 `curvy`（微胖），独立于素材已有的 `bodyTypes`（苹果型、梨型等）。
- `gender`：`unisex`（通用，旧数据默认值）、`male`（男性）或 `female`（女性）。
- 种子补齐、恢复主数据按 `code + bodyProfile + gender` 匹配；编辑、复制、删除仍按记录 ID 操作。
- 现有 16 个通用模板，加上 4 个微胖模板及 7 个男性模板，共 27 个；不自动生成“男＋微胖”组合。

微胖模板：无限重启-微胖 / LOOP、手作侘寂-微胖 / WABI、人间失格-微胖 / VOID、虚焦胶片-微胖 / FILM。

微胖版继承原人格基础内容，穿搭素材、穿搭综述及行动建议留空。男性版继承原人格介绍和颜色，替换为指定关键词，封面使用占位图，妆发、穿搭及行动建议留待配置，不把已有参考图直接标成男性素材。关键词支持最多 8 字，以完整保留“单套有美感”。

`body-variants.js` 从现有种子生成独立副本。后台迁移版本由 7/8 升至 9，仅追加缺失组合，保留已有编辑。单模板导出文件名包含身材与性别后缀，例如 `selfit-wabi-male-template.json`；导入、保存及批量导出保留两个字段。

用户端尚未支持同人格多版本，含重复 `code` 的后台导出文件不能直接交给旧生产导入流程。未来接入需另行修改导入与报告选取规则。

验证：`node --test tests/js/report-builder-body-variants.test.cjs`。
