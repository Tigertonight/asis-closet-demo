# 默认白 T 的固定三套搭配

数据文件：`app/data/white-tee-persona-matches.v1.json`。

`persona_groups` 按 16 个小写人格代码索引，下一层是版本：

```text
persona_groups
  bolt.standard.matches      → 三套
  film.standard.matches      → 三套
  film.curvy.matches         → 三套
  …
library_groups
  standard.matches           → 全库标准版三套
  curvy.matches              → 全库微胖版三套
male
  persona_groups
    ease.standard.matches    → 男款 EASE 三套
    edge.standard.matches    → 男款 EDGE 三套
    mute.standard.matches    → 男款 MUTE 三套
    wabi.standard.matches    → 男款 WABI 三套
  library_groups
    standard.matches         → 男款全库三套
```

原有女款数据保留在顶层，所有人格都有 `standard`。`curvy` 仅保留素材库已有的 `film`、`loop`、`void`、`wabi`。共 20 个人格与版本组合，加上 2 组全库结果，每组固定、有序、互不重复地保存三套，共 66 条匹配引用（不同组允许复用同一笔记）。2026-09-11 新增独立的 `male` 分区，结构沿用 `persona_groups` / `library_groups`，四个人格加全库共 5 组、15 条引用。总计 27 组、81 条，原女款 66 条选择和理由保持不变。

固化原女款匹配时，全库包含 96 套笔记，按素材的 `bodyProfile` 分为标准版 80 套、微胖版 16 套。全库组不限制人格，仍按版本区分；标准版固定为「披衫牛仔、自在都市、风衣叠穿」，微胖版固定为「正肩叠穿、斜肩针织、蓝色花苞」。顶层的候选数量仍保留这一快照。男款候选为另行导入的 16 套，数量记录在 `male.candidate_pool_size` 和 `male.candidate_pool_sizes.standard`。固定选择均已落盘，运行时不按目录顺序取前三个，也不触发模型评分。

男款按顺序选择如下，选款理由已结合白 T 的纯色圆领、宽直轮廓，以及保留单品的配色、层次和廓形写入 JSON：

| 分组 | 第一套 | 第二套 | 第三套 |
| --- | --- | --- | --- |
| EASE | 灰绿机能 | 亨利针织 | 条纹亚麻 |
| EDGE | 蓝 T 牛仔 | 迷彩印花 | 点彩街头 |
| MUTE | 黑灰牛仔 | 哈灵顿夹克 | 灰蓝针织 |
| WABI | 灰调阔腿 | 军绿工装 | 做旧亚麻 |
| 男款全库 | 灰绿机能 | 黑灰牛仔 | 灰调阔腿 |

每次仅替换明确指定的一件 `top`。例如「蓝 T 牛仔」替换内层白 T，保留外层蓝 T；「黑灰牛仔」替换原白 T，保留深灰针织层。其余单品的图片、穿法和层次保留，配对引用更新到用户白 T，不继承被替换衬衫或针织衫的外观与穿法。没有男款微胖素材，因此不创建男款 `curvy` 分组。

每条匹配保留以下字段：

- `candidate_id`：拆款数据中的 `look_id`。
- `replace_item_id`：该笔记内被白 T 替换的原始单品 ID，必须是 `top`。
- `reason`：白 T 与保留单品的搭配理由。

图片链接、其余单品和套装 ID 由真实拆款数据解析，不在此文件复制。默认白 T 的 ID 为 `6cfcffd0a4c66d10`。

后端先读取当前认证账号的 `gender`，再选择账号已保存的人格对应版本。男性账号只读取 `male` 分区，其他账号沿用原女款分区；客户端查询参数、请求体或切换模特不会覆盖账号性别。无测试报告、该人格未覆盖或个别引用失效时，只使用同性别、同版本的 `library_groups` 补到三套，并去重。引用指向异性素材时跳过，无法凑齐三套则返回错误，不临时选择未落盘的笔记。男款分区缺失也不会降级返回女款。

接口 `POST /selfit/try-on/items/{item_id}/outfits` 默认读取 `standard`；女款传 `?body_profile=curvy` 可读取微胖版，男款该请求返回 422 并提示选择标准版。成功响应增加 `gender` 字段。该参数用于默认白 T 的预设匹配，不改变普通上传单品的 AI 匹配流程。人格仍从账号报告读取。当前前端未传版本时沿用标准版，不根据模特或身体特征自行推断。

这里固化的是“白 T 替换上衣”的搭配方案。2026-09-11 已另外生成男款白 T 版试穿图，保存后的完整搭配可命中这一组专用预设，不复用原套装的旧上衣图片。女款此前暂停，现已按用户要求恢复，使用当前三位自拍女模特。

修改后运行 `python -m pytest tests/test_selfit_outfit_match.py`，校验全部分组的数量、引用、替换品类、体型版本及生成结果。

## 男款白 T 试穿预设（2026-09-11）

四个人格与全库的 15 条匹配引用去重后是 12 套，全部已为当前默认男模特 `male_standard_1` 生成 1792 × 2400 图片，上传既有七牛桶，并回读校验 SHA-256。专用索引为 `app/data/white-tee-tryon-presets.v1.json`，与原套装的 `tryon-examples.v1.json` 分开维护。

`app/white_tee_presets.py` 从匹配 JSON 和实际拆款数据构造唯一配方。离线生成与在线命中使用相同的单品顺序、真实白 T 图片及描述；仅替换指定上衣，保留外层、下装、鞋包、配饰和穿法。配方指纹覆盖原拆款、白 T 图片字节及描述，模特另校验当前主数据与照片字节。

用户点击“保存并试穿”后，后端先验证当前账号实际拥有的搭配，再比较完整单品组成、图片、穿法、配方与模特。全部一致且预设已上传、通过目检时，沿用已有约 3 秒 loading、图片解码等待及试穿历史记录流程；换模特、上传自拍、选部分单品或修改素材时回到正常生成。不能通过客户端声称配方 ID 来复用他人的搭配。

本批使用内置 `image_gen`，每套把白 T 和保留单品放在同一参考板中完整生成，逐张检查服装与人物；面部、背景检查沿用既有阈值。两张戴帽图片首次检查未通过，保留失败记录后重做。WABI「军绿工装」的墨镜放在帽顶，EDGE「蓝 T 牛仔」的渔夫帽后倾，保留面部与刘海；全部单品保留，细小纹理仍属于生成近似。

生成入口：`scripts/batch_white_tee_presets.py`，支持 `status`、`advance`、`ingest`、`publish`，准备请求与登记结果均可断点继续。`publish` 逐张检查当前配方、模特、原生工具回执、画幅、结果哈希和目检记录，上传后回读校验，不将失败或未复核图片登记为可用预设。

男款本地批次在 `outputs/tryon-examples/white-tee-20260911/`，保留配方快照、输入参考、原生输出、重试、质量记录与上传回执。该批次的女款曾按用户要求暂停，其中 2 张旧模特草稿未上传或接入；恢复生成后使用下文的新批次。图片与过程文件均被 Git 忽略。男款接入测试覆盖所有 12 套保存后的命中、原套装不混用、账号隔离、过期输入回退、失败结果拒绝，以及试穿历史与 3 秒等待。

验收：77 项 Python 回归通过，前端预设等待、图片解码、重复点击及失败恢复检查通过。隔离账号实际“保存并试穿”命中男款白 T 预设，loading 约 3.00 秒，历史页可看到新记录。393px、430px 和 1440px 页面目检通过，无横向溢出、按钮遮挡、损坏资源或脚本错误。完整证据见批次目录的 `final-validation.json`、`browser-validation.json` 和截图。本批完成本地代码接入与 OSS 素材上传，未执行服务器代码发布。
