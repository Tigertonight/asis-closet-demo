# Selfit V2 服饰库：服装设计师审查
日期：2026-09-03
版本：2026.09-v2-published1
## 结论

600 件单品和 1,200 条穿搭记录的工程数量达标，但不等于 1,200 套都有充分的款式差异、人格依据和实穿合理性。当前适合作为待精修的内容生产库，不宜把 published 或 designer_reviewed 视为严格审美验收已经完成。

主观专业视角评分：单品图像/材质表达 7/10；有效丰富度 5/10；人格辨识 5/10；场景与组合约束 4/10；整体约 5.5/10。分数是本次观察判断，不是用户实验或独立盲审结果。

优先级应从“继续增加图片”转向“淘汰重复配方、修正标签、重组主配方、再验证替换版本”。大多数素材值得保留；需要被 pass 的往往是当前组合、推荐场景或人格归属，不是单品文件本身。

## 审查范围与限制

- 全量读取正式清单的 600 件单品、480 主配方、720 替换配方。
- 浏览 16 张人格联系表，涵盖 1,200 张穿搭缩略图。
- 放大复核 10 套具体穿搭和 6 件单品。
- 检查生成配方、平铺和发布脚本，核对“已审核”字段如何产生。
- 这不是 1,200 套逐件高分辨率验收，也不是盲审：查看时知道人格标签。
- 未做真实人体上身、实物面料/工艺验证；没有可报告的独立 Top-1/Top-2 人格识别率。
- 只新增本报告与可追溯 JSON；没有改动发布池、资产或审核状态。

## 一、数量丰富与有效丰富的差别

| 指标 | 全量统计 | 设计意义 |
| --- | ---: | --- |
| 单品总量 | 600 | 品类配额达标，不代表 600 种独立设计语言 |
| 主/替换配方 | 480 / 720 | 720 个版本均只替换上装或连衣裙 |
| 去重后单品集合 | 1,187 | 13 组完全相同组合，各有一条冗余记录 |
| 被配方实际使用的单品 | 511 | 85.2% 的资产参与组合 |
| 未使用单品 | 89 | 外套17、半裙5、连衣裙13、帽30、围巾20、其他配饰4 |
| 主配方构成模板 | 4 类 | 上装裤装、上装半裙、上装裤装外套、连衣裙；组合结构单调 |
| 全部帽子/围巾使用情况 | 0 / 50 | 最容易做人格差异和季节变化的配件没有发挥作用 |
| LOOP：75套用到的独立主角 | 10 | 标题数量明显高于视觉新鲜度 |
| JADE：75套用到的独立主角 | 11 | 整体统一，但多套有重复体验 |
| MUTE：75套用到的独立主角 | 52 | 来源广泛，却容易冲淡人格边界 |

“主角”按当前 slot_roles=hero 字段计算，并不保证它是画面里最抢眼的一件。独立单品按 ID 计数，也不等于独立款式数量。

值得保留：基础衬衫、素色裙裤、鞋包整体有可复用价值。EASE 亚麻衬衫 ease-top-0016 的落肩、柔软褶皱与自然材质表达准确；NOIR 长皮衣 noir-outer-0066 的强肩与纵向轮廓清楚。

可惜 NOIR 这件长皮衣没有进入任何配方；EASE 这件衬衫只出现在 HEIR/WABI 的4套方案中。这说明一部分问题来自选配机制，不是资产缺少。

相邻人格共享单品是合理的，不能因为单品最初属于另一人格就判不合格。但 EASE 的75套主角全部来自以其他人格为最高亲和度的单品，而自身主角未进入，值得优先检查选配偏置。

当前所有配方给主人格固定赋予0.96亲和度；它是生成设定，不是图片识别或盲审测量。不能据此宣称人格匹配率96%或100%。

## 五、为什么当前规则没有挡住问题

1. **实际配色未入库。**600件单品和1,200套配方的color.palette全空；上层冷暖/饱和度由人格模板赋值，不能代表最终图片中的真实颜色。
2. **体型和比例没有真实标注。**1,200套共用同一structure描述，且全部标适合五种体型；400件服装统一fit=合体。这无法支撑可靠的结构适配推荐。
3. **内外层关系缺失。**全部layer_graph为空，平铺只按品类盒子粘贴；“每件出现一次”不等于“层次能穿”或“无遮挡”。
4. **替换约束是声明，不是完整执行。**replacement_rules写了色彩和正式度保护，但选择器没有实际计算图片颜色和单品正式度；600件单品也没有formality字段。
5. **追求不重复压过搭配性。**选配排序优先近期出现次数和使用次数，场景不是硬门槛，缺少一个完整的成套审美复核步骤。
6. **视觉审核标记过于宽泛。**平铺脚本把designer-approved参数写入多个QA布尔值；发布脚本再将置信度统一为1.0、清空review_notes。这些记录不足以证明逐套独立设计师或盲审验收。

代码定位：
- scripts/build_selfit_content_expansion.py：_job、_master_composition、_choose、build_outfits。
- scripts/build_selfit_outfit_flatlay.py：build_from_plan及designer_approved写入逻辑。
- scripts/publish_selfit_content_pool_v2.py：build覆盖annotation的逻辑。

## 六、建议整改顺序（本次未执行）

1. **先清理确定性问题。**去重13条；将上述具体方案按“改场景、改人格、重配”分流，保留可复用素材。
2. **先修数据再重排。**逐件补实际主辅色、材质、版型、衣长/袖型、装饰等级、正式度、温度适用与内外层。
3. **重建480套主配方。**每套1个清晰主角+支撑款；典型款有至少一个可读人格锚点；入门款允许安静但不能完全失去人格差异。
4. **先用未使用的89件。**优先NOIR长外套、帽和围巾；为JADE/LOOP增加不同主角，不靠标题和微小换色补量。
5. **重做720个版本。**替换主角后重新审核全套，允许为协调而联动鞋包；同时增加外套/鞋/包/围巾的有意义替换。
6. **做可追溯盲审。**隐藏人格名，记录审阅者Top-2、理由、场景可用性与不合格项；没有结果时不输出“匹配率达标”。
7. **审核状态分开。**资产技术合格、搭配审美合格、人格归属合格、场景可用四个状态独立保存；不再用一个published概括全部。

建议先验收每人格10套高质量锚点（共160套），验证规则后再重配其余内容。最终仍可达到1,200套，但不要为维持整数目标放行明确有问题的方案。
