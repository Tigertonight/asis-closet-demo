# Mirro 拍照模板能力设计

## 1. 产品定位

这是 Mirro 拍照后的独立成片工具，不进入 Mirro 原工程目录。目标是让运营或现场用户在 1 分钟内完成：

1. 导入 Mirro 原图；
2. 自动套用品牌 LUT 与轻质感处理；
3. 选择模板并微调构图；
4. 微调照片在素材窗口中的位置；
5. 导出可直接分享的高清 PNG。

主体验围绕“照片最后长什么样”，不暴露 shader、mask、prefab 等技术概念。

## 2. 信息架构

- 外层批次工作台：多张导入、选择、统一处理、状态跟踪和集中导出。
- 顶栏：项目名、重置、导出。
- 左栏：原图与模板选择。
- 中央：实时画布、成片/原图对比、预览缩放、拖动构图。
- 右栏：画面参数。

所有编辑都在一个页面完成，避免多步骤跳转打断对画面的判断。

批次工作台中的每张照片拥有 `未处理 / 处理中 / 已完成 / 处理失败` 四种状态。队列按顺序处理以控制浏览器内存峰值；完成项保留 PNG Blob，用户多选后由浏览器打包为 ZIP 下载。刷新页面会清空批次，避免持久化用户照片。

## 3. 模板系统

模板由固定输出尺寸、照片槽位和原始透明 PNG 覆盖层组成。覆盖层来自 `02_MATERIAL_SINGLE.zip`，保持原素材的纹理、阴影和蕾丝细节，不做重新绘制，也不参与 LUT 处理：

| 模板 | 输出尺寸 | 场景 |
|---|---:|---|
| 酒红硬边框 | 1080×1440 | 酒红布面与利落黑边，偏经典 |
| 银灰硬边框 | 1080×1440 | 银灰布面与利落黑边，偏清冷 |
| 酒红蕾丝框 | 1080×1440 | 酒红布面与白色蕾丝，偏复古 |
| 银灰蕾丝框 | 1080×1440 | 银灰布面与白色蕾丝，偏轻盈 |

照片只绘制到透明窗口内，使用 cover 裁切，用户可统一缩放并拖动焦点；随后在最上层绘制原始 PNG 素材，保证照片不会遮住边框。

## 4. 效果包映射

附件 `撕拉片.zip` 中识别到四个效果组：

| 原效果 | 原默认值 | Web 映射 |
|---|---:|---|
| Vignette / 暗角 | 50 | 径向正片叠底，最大约 28% |
| FilterwithSkin / 双 LUT | 80 | 512×512 8×8 LUT；肤色与背景分别采样后混合 |
| Blur / 高斯模糊 | X=10, Y=10, intensity=50 | 轻微预柔化，可调 0–30 |
| Noise / 细噪 | 50 | 固定种子的细颗粒，确保重复导出一致 |

原 SDK 的人像分割 mask 不包含在附件中。当前 Web 版用 YCbCr 肤色概率生成软混合权重，避免人物肤色被背景 LUT 过度影响。若 Mirro 后续提供真实人像 mask，只需替换 `skinProbability()` 的权重来源，模板与导出逻辑无需改变。

## 5. LUT 兼容

- 内置：附件中的 `filter_skin.png` 与 `filter_bg.png`。
- 自定义 PNG：512×512、8×8 分块、64 级蓝通道。
- 自定义 CUBE：标准 `LUT_3D_SIZE` 与 RGB 数据，使用三线性插值。
- 强度：0–100%，按原色与 LUT 结果线性混合。

原 shader 以 OpenGL 底部为纹理原点；Canvas 以顶部为图片原点。实现中去除了 shader 的 Y 反转，保证同一张 LUT 在浏览器中不会出现红/青反色。

## 6. 隐私与性能

- 文件通过 `ObjectURL` 解码，不发起上传请求。
- LUT 与图片处理全部运行在浏览器 Canvas 中。
- 处理图最长边限制为 1600px，保证 PC 实时预览速度。
- 最终模板仍按 1080px 原始画布导出。
- 照片、标题和编辑参数不写入本地存储，刷新即清除。

## 7. 后续生产化接口

建议 Mirro 交付给本工具的最小对象：

```json
{
  "photoUrl": "blob-or-signed-url",
  "portraitMaskUrl": "optional-mask-url",
  "captureId": "mirro-capture-id",
  "capturedAt": "2026-08-28T17:00:00+08:00"
}
```

如果使用签名 URL，应只在内存中读取，不持久化；导出文件名可使用 `captureId + templateId`，方便回溯。
